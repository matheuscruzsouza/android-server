S4 • Simple Shared Storage Service

nano-spring 2.4.0 Showcase

Serviço de Armazenamento de Objetos e Servidor de Arquivos com compatibilidade total ao protocolo Amazon S3, controle de acesso granular IAM e interface Desktop Explorer moderna (estilo Windows 11 Explorer) executando diretamente no Android.

🪣 Protocolo S3 Nativo 🔐 AWS SigV4 Criptográfico 💻 Desktop Explorer Web UI 🌐 Resolução mDNS (s4.local) ⚡ Otimizado para Android 7.1.1+
🏛️

Arquitetura Modular nano-spring 2.4.0

O S4 é construído sobre a suíte desacoplada do nano-spring 2.4.0, garantindo pegada de memória mínima e carregamento instantâneo:

● nano-spring-core
IoC / DI container ultra-leve, injeção de dependência via @Autowired, @Service, @Value e ciclo de vida.
● nano-spring-web
Servidor HTTP assíncrono baseado em NanoHTTPD, roteamento @RestController, interceptores, SSE e SSR JMustache.
● nano-spring-data
Abstração de repositórios @Repository, injeção do SQLiteDatabase e migrações versionadas com SqliteMigrator.
● nano-spring-discovery
Descoberta Zeroconf/DNS-SD (NsdServiceManager) e resolução mDNS (MdnsHostResponder) para acesso direto via s4.local.
app/build.gradle 
dependencies {
    implementation 'com.github.matheuscruzsouza:nano-spring-core:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-web:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-data:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-discovery:2.4.0'
}

Gateway S3 & Operações na Raiz

O S4 atua como um storage de objetos S3 autêntico, aceitando requisições no padrão /{bucket}/{key} diretamente na raiz e com retrocompatibilidade pelo prefixo /s3/.

💡 Zero Dependência Proprietária: Ferramentas como o AWS CLI e Rclone apontam diretamente para o endpoint raiz sem qualquer shim ou adaptador intermediário.
Ação S3 Verbo Rota Descrição
ListBuckets GET / ou /s3 Retorna XML formatado dos buckets existentes
CreateBucket PUT /{bucket} Criação do bucket no armazenamento físico do dispositivo
HeadBucket HEAD /{bucket} Verifica existência e permissões do bucket (HTTP 200)
ListObjectsV2 GET /{bucket}?list-type=2 Listagem de objetos com suporte a cursor e prefixo
PutObject PUT /{bucket}/{key} Upload de objeto com streaming direto para arquivo em disco
GetObject GET /{bucket}/{key} Download com suporte a Range Requests (HTTP 206)
HeadObject HEAD /{bucket}/{key} Metadados, Content-Length, ETag e MIME-type
DeleteObject DELETE /{bucket}/{key} Remove o objeto do bucket com resposta HTTP 204
DeleteObjects POST /{bucket}?delete Exclusão em lote com parsing de XML e resposta estruturada

AWS Signature Version 4 & Presigned URLs

O S4 implementa internamente o algoritmo criptográfico oficial da AWS para verificação de assinaturas SigV4:

🔑 Cabeçalho HTTP Authorization
Validação no padrão AWS4-HMAC-SHA256 Credential=AKIA.../20261101/us-east-1/s3/aws4_request, SignedHeaders=..., Signature=....
🔗 Presigned URLs
Autenticação via parâmetros de query string (X-Amz-Signature, X-Amz-Credential, X-Amz-Expires).

Guia Prático: AWS CLI, rclone & MinIO mc

Instruções exatas para operar seu servidor S4 usando ferramentas de linha de comando:

1. Configuração do AWS CLI

Configuração de Perfil 
# Configurar perfil s4
aws configure --profile s4
# AWS Access Key ID: admin
# AWS Secret Access Key: (sua secret key)
# Default region: us-east-1
# Default output format: json

export ENDPOINT="http://s4.local:9090"

2. Comandos Diários com AWS CLI

Comandos de Exemplo 
# Criar um bucket
aws --profile s4 --endpoint-url "$ENDPOINT" s3 mb s3://fotos

# Enviar arquivo
aws --profile s4 --endpoint-url "$ENDPOINT" s3 cp foto.jpg s3://fotos/foto.jpg

# Listar objetos
aws --profile s4 --endpoint-url "$ENDPOINT" s3 ls s3://fotos/

# Baixar arquivo
aws --profile s4 --endpoint-url "$ENDPOINT" s3 cp s3://fotos/foto.jpg ./foto_download.jpg

# Excluir objeto
aws --profile s4 --endpoint-url "$ENDPOINT" s3 rm s3://fotos/foto.jpg

3. Sincronização Automática com Rclone

No arquivo ~/.config/rclone/rclone.conf:

~/.config/rclone/rclone.conf 
[s4]
type = s3
provider = Other
env_auth = false
access_key_id = admin
secret_access_key = sua-secret-key
endpoint = http://s4.local:9090
region = us-east-1
acl = private

Mini-IAM & Segurança Nativa

Controle de acesso granular baseado em credenciais armazenadas no SQLite interno do Android:

Política Permissões Cenários de Aplicação
Admin Acesso total a leitura, gravação, exclusão, buckets e gestão de usuários IAM Administrador e proprietário do dispositivo
ReadOnly Apenas listagem e download de objetos (GetObject, ListObjects) Compartilhamento público de biblioteca de mídia
WriteOnly Apenas upload de novos objetos (PutObject) sem leitura ou exclusão Câmeras de segurança, logs de IoT e backups automáticos

Resolução de Host mDNS (s4.local)

Graças ao módulo nano-spring-discovery e ao MdnsHostResponder, o S4 responde ativamente a consultas Multicast DNS (registro tipo A na porta UDP 5353):

app/src/main/assets/application.properties 
nano.nsd.enabled=true
nano.nsd.name=s4
nano.nsd.type=_http._tcp.
nano.nsd.host-resolution=true
✨ Zero Configuração de DNS: Digite http://s4.local:9090/ no Google Chrome, Edge ou Safari para abrir o Explorer a partir de qualquer computador na rede local.
