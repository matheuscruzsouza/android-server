🏛️ Arquitetura Modular nano-spring 2.4.0

O S4 é construído sobre a arquitetura modular desacoplada do nano-spring 2.4.0, garantindo pegada de memória mínima e inicialização quase instantânea.

📦 nano-spring-core

IoC / DI container ultra-leve, injeção de dependência via @Autowired, @Service, @Value, ciclo de vida de componentes e mensageria interna.

🌐 nano-spring-web

Servidor HTTP assíncrono baseado em NanoHTTPD, roteamento @RestController, interceptores de segurança, SSR JMustache e Server-Sent Events (SSE).

🗄️ nano-spring-data

Abstração de repositórios @Repository, injeção do SQLiteDatabase gerenciado e migrações versionadas estilo Flyway com SqliteMigrator.

🔍 nano-spring-discovery

Descoberta na rede local Zeroconf/DNS-SD (NsdServiceManager) e resolução nativa de Host mDNS (MdnsHostResponder) para acesso direto via s4.local.

build.gradle (app) 
dependencies {
    implementation 'com.github.matheuscruzsouza:nano-spring-core:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-web:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-data:2.4.0'
    implementation 'com.github.matheuscruzsouza:nano-spring-discovery:2.4.0'
}

🪣 Gateway S3 & Roteamento na Raiz

O S4 atua como um storage de objetos S3 autêntico, aceitando requisições no padrão /{bucket}/{key} diretamente na raiz e com retrocompatibilidade pelo prefixo /s3/.

💡
Compatibilidade sem Shims: Ao configurar clientes como AWS CLI ou Rclone, basta apontar o endpoint-url para a raiz do servidor (ex.: http://192.168.1.100:9090). Não há necessidade de adaptadores proprietários.

Operações S3 Suportadas

Ação S3 Método HTTP Rota Descrição
ListBuckets GET / ou /s3 Retorna XML compatível com os buckets disponíveis
CreateBucket PUT /{bucket} Cria novo bucket no diretório isolado de storage
HeadBucket HEAD /{bucket} Verifica a existência do bucket e permissões (200 OK)
ListObjectsV2 GET /{bucket}?list-type=2 Listagem paginada com cursor real, prefix e continuation-token
PutObject PUT /{bucket}/{key} Upload de objeto com streaming direto para disco temporário
GetObject GET /{bucket}/{key} Download com suporte a Range Requests (HTTP 206)
HeadObject HEAD /{bucket}/{key} Retorna Content-Length, ETag, MIME-Type e Accept-Ranges
DeleteObject DELETE /{bucket}/{key} Remove o objeto do bucket com resposta 204 No Content
DeleteObjects POST /{bucket}?delete Exclusão em lote com parsing de XML e relatório de status

🔐 AWS Signature Version 4 & Presigned URLs

O S4 implementa internamente o algoritmo criptográfico completo da AWS para verificação de assinaturas SigV4.

Todas as requisições autenticadas passam pelo IamSecurityInterceptor, validando:

  • Authorization Header: Padrão AWS4-HMAC-SHA256 Credential=...
  • Presigned URLs: Assinaturas na query string (X-Amz-Signature, X-Amz-Credential, X-Amz-Date, X-Amz-Expires).
  • Derivação de Chaves de 4 Etapas: HMAC-SHA256("AWS4" + SecretKey, Date) -> Region -> Service -> SigningKey.
  • Canonical Request & StringToSign: Comparação segura de hashes imune a timing attacks.

🛠️ Guia Prático: AWS CLI, Rclone e MinIO Client

Comandos prontas para uso em terminal e scripts de automação.

1. Configuração do AWS CLI

Configuração de Perfil 
# Configurar credenciais do S4
aws configure --profile s4
# AWS Access Key ID: admin
# AWS Secret Access Key: (sua Secret Key gerada no IAM)
# Default region: us-east-1
# Default output format: json

# Definir endpoint do servidor no Android
export ENDPOINT="http://s4.local:9090"

2. Operações de Bucket e Arquivos

Comandos S3 Comuns 
# Criar um novo bucket
aws --profile s4 --endpoint-url "$ENDPOINT" s3 mb s3://backups

# Listar buckets
aws --profile s4 --endpoint-url "$ENDPOINT" s3 ls

# Upload de arquivo simples
aws --profile s4 --endpoint-url "$ENDPOINT" s3 cp foto.jpg s3://backups/foto.jpg

# Download com suporte a streaming
aws --profile s4 --endpoint-url "$ENDPOINT" s3 cp s3://backups/foto.jpg ./foto_baixada.jpg

# Listar conteúdo de um bucket
aws --profile s4 --endpoint-url "$ENDPOINT" s3 ls s3://backups/

# Excluir objeto
aws --profile s4 --endpoint-url "$ENDPOINT" s3 rm s3://backups/foto.jpg

3. Configuração com Rclone (Sincronização Contínua)

No arquivo ~/.config/rclone/rclone.conf:

rclone.conf 
[s4]
type = s3
provider = Other
env_auth = false
access_key_id = admin
secret_access_key = sua-secret-key-aqui
endpoint = http://s4.local:9090
region = us-east-1
acl = private

Para sincronizar uma pasta local com seu Android:

Terminal 
rclone sync ~/Documentos s4:backups/documentos -P

👤 Mini-IAM & Segurança Nativa

Controle de acesso granular baseado em credenciais gerenciadas no próprio SQLite do Android.

Política (Role) Permissões Casos de Uso
Admin Acesso irrestrito a leitura, escrita, deleção, criação de buckets e gerenciamento de usuários IAM Administrador do dispositivo / dono da conta
ReadOnly Permissão exclusiva de listagem e download (GetObject, ListObjects) Compartilhamento público de biblioteca de mídia ou documentos
WriteOnly Apenas upload de novos objetos (PutObject) sem permissão de leitura ou exclusão Câmeras de segurança, logs de sensores IoT e backups automáticos

🌐 Resolução de Host mDNS (s4.local)

Acesso transparente a partir de qualquer navegador da rede sem necessidade de digitar endereços IP.

Graças ao módulo nano-spring-discovery e ao MdnsHostResponder, o S4 escuta e responde ativamente a requisições de Multicast DNS (registro tipo A na porta UDP 5353).

application.properties 
nano.nsd.enabled=true
nano.nsd.name=s4
nano.nsd.type=_http._tcp.
nano.nsd.host-resolution=true
✨
Acesso Direto: Ao iniciar o servidor no smartphone, qualquer computador na mesma rede Wi-Fi (seja Windows 10/11, macOS ou Linux com Avahi) pode acessar diretamente http://s4.local:9090/ sem instalar qualquer plugin.

📦 SQLite Migrator Integrado

Evolução controlada e automatizada do esquema de dados SQLite estilo Flyway.

As migrações são lidas automaticamente do diretório assets/db/migration/ no empacotamento do APK:

Versão Script SQL Responsabilidade
V1 V1__init_server_events.sql Cria tabela de auditoria e telemetria de eventos do servidor
V2 V2__init_iam.sql Estrutura tabelas de usuários IAM, access keys, tokens de registro e políticas
V3 V3__migrate_legacy_users.sql Migra usuários legados da versão anterior para o novo formato de credenciais IAM
